# Project working rules
- Build Stillroom for learners balancing study with work and life. Keep its nocturnal, calm, lavender visual identity.
- Each day, read this file, BACKLOG.md and Git status, review the prior code/diff and debug defects before today's ticket.
- Every session includes code review, behavior-focused tests, today's implementation, docs/backlog updates, debugging and final review. Run tests/typecheck/build when dependencies are installed.
- Make planning supportive and flexible. Never use progress metrics to shame users or imply that a missed day is failure.
- Preserve responsive layouts, light/dark themes, keyboard access, reduced-motion behavior and clear timer state announcements.
- Use React, TypeScript, Vite, shadcn/ui-style local components, Radix primitives, Tailwind and React Icons. Keep timing logic isolated and testable.
- Update BACKLOG.md every session, record discoveries and leave tomorrow's scope explicit.
- Keep .npmrc ignored and local. Do not commit credentials, private learner data, .env or build output. Never force-push or rewrite history.
- Work only in this repository; make meaningful commits after checks pass.
